# 0001. 設計判断の記録に ADR を採用する

- Status: Accepted
- Date: 2026-10-03

## Context

リポジトリの設計判断は、当初 `docs/MoneyForward Suite 設計・要求ドキュメント.md`（53 セクション・1303 行）の単一文書で管理していた。この文書には性質の異なる内容が混在していた。

- 設計判断（アーキテクチャ・セキュリティ・運用の方針）
- 要件とロードマップ（進捗に応じて書き換わる）
- 現在の構造の説明

そのため、判断の更新と要件の更新が同じ文書を書き換えることになり、どこを更新すべきか曖昧で、全体が陳腐化しやすい。決定の変更履歴（いつ・なぜ変えたか）も残らない。「Codex MUST」のように、実装主体を特定ツール名で固定した記述が残る問題もあった。

## Decision

設計判断の記録に ADR（Architecture Decision Record）を採用し、単一の設計書は廃止する。文書を役割で 3 層に分ける。

- 決定の記録: ADR（このディレクトリ）。不変。
- 要件・ロードマップ: 要件文書（生きている文書。進捗に応じて更新する）。
- 現在の構造: アーキテクチャ文書（生きている文書。ADR 索引への入口を兼ねる）。

書式は MADR 簡略版、粒度は 1 決定 1 ファイルとし、詳細な運用規約は [README](README.md) に定める。既存設計書の内容は ADR-0002 以降へ遡及記録（retrospective）として移行し、設計書は削除する（移行は Issue #21）。ADR-0002 以降の Date は、原典が記録された日付（2026-10-03）を示す。

## Consequences

- 決定が不変の記録として残り、変更時は新しい ADR で置き換えるため、変更の履歴と理由を追跡できる。
- 決定ごとにファイルが分かれ、決定単位でのレビュー・参照・差し替えができる。
- 現在の全体像は ADR を横断しないと分からないため、現状を説明する文書（アーキテクチャ文書）を別に維持し、ADR 索引への入口とする。
- 遡及記録では、原典に検討記録がない代替案を推測で再構成しない。記録がない場合はその旨を明記する。
- 設計書にあった要約（Codex MUST / MUST NOT 等）は個別 ADR へ分解され、要約そのものは残らない。追跡は ADR 番号で行う。

## Alternatives considered

- 単一の設計書を維持する: 陳腐化しやすく変更履歴も残らないという課題が解決しないため却下。
- 設計書を複数文書（アーキテクチャ・要件・セキュリティ等）へ分割するだけにする: 役割の混在は緩和されるが、決定の変更履歴が残らないため却下。
- 決定を 1 ファイルへ集約する（decisions.md）: 決定の増加に伴い、どの決定が生きているか読めなくなるため却下。
